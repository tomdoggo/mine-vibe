# 篮球模拟 Demo

俯视视角的 5v5 篮球比赛模拟：场上 10 名球员全部自主决策（投篮 / 传球 / 突破 / 空切 / 盯人 / 抢断 / 抢篮板），
没有任何玩家操作，只能看、调速度、翻数据。

## 启动

```bash
cd basketball-demo
npm install
npm run dev
```

浏览器打开 http://localhost:5174

## 赛季模式（打开页面默认进入）

- **球员库 / 球队库**：`src/data/db/players.json`（500 人，其中 115 名有真实原型的传奇）、`teams.json`（50 队，每队 10 人；位置只是装饰，综合能力最高的 5 人首发）。
  由 `scripts/build-db.ts` 生成：传奇和历史球队手写在脚本里，其余名额按固定种子生成虚构球员。改完重新生成：`npm run db`。
  - 强队 10 支（96 公牛、87 湖人、86 / 65 凯尔特人、17 勇士、01 湖人、14 马刺、67 七六人、13 热火、89 活塞），核心阵容几乎都是传奇；
  - 普通队 20 支（95 火箭、98 爵士、04 活塞、23 掘金……），2~4 名传奇 + 角色球员；
  - 杂牌队 20 支（城郊野狼队、外卖骑手队……），全员虚构、很弱。
  - 每名传奇只属于一支球队（他最巅峰的那支），同一赛季不会出现两个乔丹。综合能力 = 八项里最好的六项平均（`lineup.ts` 的 `ovr`）。
- **赛季**（`src/season/Season.ts`）：每季从 50 队随机抽 10 队，四循环（每两队打 4 场，主客场各 2 场；每队 36 场，共 180 场）。
  排名看胜场 → 相互战绩 → 净胜分。前 4 名进季后赛：半决赛 1 vs 4、2 vs 3，总决赛，全部三局两胜（主场：高-低-高），主场给排名高的一方。
- **奖项**：常规赛 MVP（场均效率 ×（0.6 + 0.8 × 球队胜率））、总决赛 MVP（冠军队总决赛场均效率）、得分王、助攻王、篮板王、抢断王、盖帽王、最佳第六人（替补出场多于首发的球员里效率最高）。
  每项显示前三，第一名获奖；个人奖要求常规赛出场 ≥ 球队场次的 60%。效率 = 得分 + 篮板 + 助攻 + 抢断 + 盖帽 − 投丢 − 罚丢 − 失误。
- **观看与模拟**：每场比赛有固定种子，所以「观看」和「后台模拟」得到的是同一场比赛，打完的比赛可以「回看」原样重放。
  伤病会带到之后的比赛，所以一场比赛要等两队之前的比赛都打完才能开打（`readyGames`），开打时定下的伤病名单存在比赛里（`setup`），回看沿用。
  后台模拟用多个 Web Worker 并行（`simPool.ts`、`sim.worker.ts`），同一轮互不相关的比赛并行跑。赛季存在 localStorage，刷新不丢。
- **伤病**（`src/sim/injury.ts`）：场上每个动作（投篮、传球、突破、空切、抢断、争篮板、封盖、罚球）都有一次受伤判定，
  概率 = 0.00013 × e^(−稳定性 / 35)（用当前实际稳定性，累了更容易伤）。首发每场约 400 个动作，所以一个赛季（36 场）受伤的概率：
  稳定性 0 约 85%、50 约 35%、70 约 23%、90 约 13%。75% 轻伤（能力减半，之后 1~3 场带伤上场），20% 重伤（能力减半且缺阵 3~5 场），5% 赛季报销。
  本场受伤：轻伤继续打，剩余上场时间砍掉六成；重伤 / 报销下一个死球被换下。之后的比赛（`db.ts` 的 `arrangeRoster`）：缺阵的人不进名单，
  每场按综合能力（轻伤减半）从高到低排名单，前 5 人首发；伤停的人不在名单里，带轻伤的人按减半后的实力排、出场时间也按它分。
- **新闻**：受伤（轻伤 n 场 / 重伤缺阵 n 场 / 赛季报销）、3/5/7/10 连胜及之后每 5 场、5 连胜以上被终结、
  MVP 周榜（每 3 轮结算一次，只看到那一轮为止的比赛：登上榜首 / 连续 n 周领先）、季后赛晋级、总冠军、赛季奖项出炉。
- **加时**：常规时间打平就加时 5 分钟，直到分出胜负（进度条和统计图只画常规时间 40 分钟）。

### 教练与体力

- **教练**（`src/sim/coach.ts`）：开场前定好每人的目标出场时间：首发约 30 分钟（综合能力比首发平均每高 1 点多 0.4 分钟，26~34），
  其余时间按（综合能力 − 45）² 分给替补（单人最多 22 分钟）。每个死球（发球前）重新挑场上五人：
  按“还欠多少出场时间 / 剩余比赛时间”排优先级，体力低于 85 开始扣分，刚上场不到 2.5 分钟的人加分；
  下半场最后 4 分钟分差 ≤ 8 时主力回场，最后 7 分钟分差 ≥ 22 时主力休息；不看位置。换人后按新五人的能力值重新分配站位。
- **体力**（`src/sim/fatigue.ts`，0~100）：场上每秒有基础消耗，跑动按距离消耗，投篮、传球、突破、空切、抢断、争篮板、封盖、罚球各有一次性消耗；
  场下每秒恢复，中场休息全员 +12。体力 ≥ 80 能力值不打折，80 以下线性衰减，体力 0 时只剩一半（所有比赛结算都用 `Player.eff`，不用 `def.attrs`）。
  校准：动作最多的明星连续打满 40 分钟大约剩 30（乔丹约 33），正常轮换下首发最低约 73~80。校验：

```bash
npm run sim:fatigue -- 4 chi1996 gsw2017   # 五人打满的终场体力 + 十人轮换的出场时间
npm run sim:season -- 7                     # 不渲染跑完一个赛季：季后赛比分、积分榜、全部奖项
MATCHUP=chi1996,gsw2017 npm run sim:replay -- 12345   # 十人名单（会换人）的回放校验
```

## 界面

- 左侧球场（24 秒计时在球场上方正中）+ 下方比赛进程；右侧数据面板按队显示 MIN / FG / 3P / FT / PTS / REB / AST / STL / BLK / TOV / PF，
  第一行是以队名标识的全队合计，下面五行球员，点球员名打开球员卡。「显示：命中率 / 命中·出手」切换投篮三列是百分比（一位小数）还是 10/17 这样的比。
  球员脚下的队色圆盘上写着位置和号码（如 PG.3）。球员模型按身高缩放：170cm 为 0.9 倍，230cm 为 1.5 倍，线性插值（`Player.ts` 的 `bodyScaleFor`）。
- 比赛进程里最近防守人在 1.2m 以外的中投 / 三分写成「空位中投」「空位三分出手」。
- 球员卡：身高 / 体重 / 年龄 / 位置、徽章（仅展示）、八项能力值（50~100）。能力值左右对称排列：左列进攻（篮下、三分、中距离、助攻），右列防守与其他（禁区防守、外线防守、篮板、稳定性），数值条从中线向两侧长；每项外侧有「?」，点击在卡片底部显示该能力值的作用（文案在 `players.ts` 的 `ATTR_HELP`）。
- 比赛为上下半场各 20 分钟；「速度 Nx」按钮在 1x → 2x → 4x → 8x 间循环，默认 1 倍速，一个半场 20 分钟现实时间，4 倍速约 5 分钟；「跳过全场」直接快进到终场。
- 回放：球场下方是比赛进度条（按比赛钟走，每 5 分钟一格，半场处一道亮线）。首次观看时锁定只能看；终场后解锁，点或拖到任意位置就回到那一刻继续播，
  回放的内容和第一遍看到的逐字一致。实现见下面的「可复现与回放」。
- 「统计图」：分钟粒度的累计数据折线图（得分 / 篮板 / 助攻 / 抢断 / 盖帽 / 失误 / 犯规 / 出手），「队伍」视图蓝红两条线，「球员」视图某队五人各一条线，
  点图例隐藏 / 显示某条线；竖线是当前时刻，图例里的数值是当前时刻所在分钟的值。比赛进行中也能看，播到哪画到哪。

## 可复现与回放

- 模拟里所有随机数都走 `src/sim/rng.ts` 的 `rng()`（带种子，mulberry32），**不要在 sim 目录里直接用 `Math.random`**，否则回放会和第一遍不一致。
- 模拟按固定步长 `STEP = 1/60` 秒推进（`MatchScene` 用累加器，倍速就是一帧多走几步），同一种子两次运行逐步完全一致。
- 整场 40 个比赛分钟，每分钟一个种子，由总种子派生（种子链）。每进入新的一分钟 `Match.update()` 重置随机数并触发 `onMinuteStart`，
  `src/replay/Timeline.ts` 在那里存一份完整快照（`Match.snapshot()`：Match / Player / Ball 的全部可变状态，球员引用存为下标）。
- 拖进度条 = 恢复目标时刻所在分钟的快照（`Match.restore()`，同时切回该分钟的种子），再按固定步长快算到目标秒（每帧最多 25 毫秒，分摊到多帧）。
  不录任何帧，内存只有 40 份快照。总种子显示在界面右上角，「再来一场」换一个新种子。
- 给 Match / Player / Ball 加新的可变字段时，必须同步加进 `snapshot()` / `restore()`，然后跑一次校验：

```bash
npm run sim:replay -- 12345
```

它同种子跑两场逐步比对，再把每个分钟快照恢复后重算一分钟与原记录逐步比对，任何漏掉的字段都会立刻报出差异。

## 能力值如何参与比赛（`src/sim/Match.ts`）

每次动作的实际值 = 能力值 + 本半场随机区间 [下限, +50] 内的随机量（见稳定性）。

- **篮下 / 中距离 / 三分投篮**：按出手位置取对应能力（离筐 2.2m 内算篮下，三分线外算三分，其余算中距离）。
  有效值 82 对应的基础命中率：篮下 79%、中距离 56%、三分 36.8%；进攻每点：篮下 0.5%、中距离 0.12%、三分 0.25%。
  中距离每点命中率低，但它决定“这球敢不敢投”：中投高的人更多机会过出手门槛，进攻更流畅；罚球也用它（有效值 82 对应 75%，每点 0.4%）。
  移动中出手：三分 −8 点、中距离 −2 点（急停干拔是中距离的特长）。
  三分对普通射手的真实收益故意定得比中投低，但 AI 决策时会把三分的期望得分高估 10%（`ai.ts` 的 `THREE_BIAS`），
  所以球员仍会正常出手三分；被防守逼到只能投三分对进攻方是真实的损失。
  站位：外线三人（PG/SG/SF）常规站三分线外，每回合有 70% 的基础概率改站中距离位，中投比三分每高 8 点加 10%（上限 80%）；
  内线按三分能力偶尔拉到线外（50 约 9% 的回合，70 约 25%，上限 30%）；中锋低位离筐 2m，出手算篮下。
  篮下比三分好得越多越爱突破；本场出手明显多于队友的人会被少传、也更少自己出手。
- **禁区防守 / 外线防守**：最近的防守人在 2m 内时产生防守点 =（防守值 − 50）× 贴近程度 × 3.7（篮下出手只算 75%），
  每个防守点扣命中率：篮下 0.5%、中距离 0.15%、三分 0.21%。进攻斜率和防守斜率分开设，互不牵连。
  用哪项防守看出手点离筐的距离，而不是防守人站在哪：2.75m 内全看禁区防守，三分线外全看外线防守，
  中间线性过渡（中距离站位 4.7m 处各占一半）。这样进攻方没法靠挪一步完全躲开某一项防守。
  封盖：篮下出手 1.5m 内的防守人有机会封盖，概率 8.5% +（防守值 − 篮下投篮值）/ 85，封盖不计入进攻方的出手预期，躲不开；
  跳投只有 1.1m 内的贴防人能封，概率低得多。
  持球抢断：0.32% × e^((防守值 − 持球人助攻值) / 32)，防守人离本方篮筐 4.5m 内用禁区防守，否则用外线防守。
  截断传球用两项防守的平均值。盯人时的脚步速度看所在区域对应的防守能力（50 → 0.85 倍速，100 → 1.1）。
- **助攻**：接到传球后 3 秒内，接球人命中率直接 +（传球人助攻期望 − 50）× 0.08%（和出手类型无关）；期间得分记传球人助攻。
  传球距离：助攻 50 只能舒服地传 8m，助攻 100 能传 14m，超出越多越不愿传、超出 4m 以上不考虑。
  传球难度：传球线路 1.2m 内每有一个对手就要多 10 点助攻才传得舒服（50 只敢传没人的线路，70 能越过两人，80 越过三人），
  不够的部分按比例打折，差 50 以上直接不传。
  截断：传球人助攻越低，线路上的对手能碰到球的半径越大（50 → 0.55m，100 → 0.33m），
  概率 18% +（防守值 − 助攻值）/ 200，线路附近每多一人再 +3%。持球人还在后场时，场上除他以外传球（助攻）最好的人回来接应。
- **篮板**：投篮不中后所有人向篮下收缩（篮板能力越高站得越近，篮板 ≥ 68 卡位），球在篮筐上弹 0.4 秒落下时，球 4.5m 内的人各掷一次：
  篮板值 × 0.078 + 距离加成 + 0~50 随机，出手者减半、防守方 +6；赢家获得 2 秒独占权，球会朝他滚过去。
- **稳定性**：每半场开始时为每名球员掷一次本半场随机区间的下限（`attrs.ts`）。默认下限 −50，
  抬高量在 [保底, 保底 + 10] 内随机，保底 =（稳定性 − 50）× 0.28，即每 10 点稳定性让所有能力平均多发挥约 1.4 点。
  球员卡上能看到本半场的区间。隐藏特性：稳定性越高无球跑位越勤（50 → 0.6 倍频率，80 → 1.27 倍，95 以上 1.5 倍）。
  跑位分两种：离筐 3.5m 外的人在篮下不挤时按篮下能力空切；外线球员换位（30% 收到中距离位，否则按能力值重挑站位，再挪 1.5~3m）。
- **犯规**：伸手抢断犯规是普通犯规，不罚球，被犯规一方重新发球。投篮被贴防（1.1m 内）时有 20% 概率吹投篮犯规：
  不中罚 2 或 3 次，中了加罚 1 次；罚球时停表，最后一罚不中则争抢篮板。

### 八项能力值的平衡

> 下面的数据是加入体力系统之前测的；体力对两队同样生效，但净胜分可能有变化，需要按原流程重测。

用 `npm run sim:sens -- attr` 测：全员 70 作基线，蓝队某一项 70 → 95，看净胜分变化。当前数值
（每项 300 场，两项防守 600 场；300 场的 95% 区间约 ±1.8）：

| 能力 | 净胜分 | 能力 | 净胜分 |
|---|---|---|---|
| 中距离投篮 | +9.3 | 禁区防守 | +7.4 |
| 助攻 | +9.0 | 稳定性 | +6.8 |
| 篮下投篮 | +7.8 | 外线防守 | +6.5 |
| 篮板 | +7.8 | 三分投篮 | +6.1 |

真实名单 100 场：均分约 104，出手结构三分 19% / 中投 52% / 篮下 29%，总命中率 45%，三分 30%，
助攻 21，抢断 10，盖帽 6，失误 10，罚球 13 次；名单互换后两队强弱差不到 1 分。

调平衡时踩过的坑：

- **防守的价值有上限**（约 +6~8）。进攻方 AI 会挑出手，防守再强也只能把对方逼到次好的选择；
  而且防守越强对手每回合耗时越长，比赛变慢，净胜分被稀释。试过加大折损系数、站得更近、补防更快、抢断更敏感，都抬不上去，
  前两种还会适得其反（只剩空位球可投 / 丢协防和篮板）。所以最后是把其余六项压到防守的水平来对齐。
- **三分和禁区防守是跷跷板**：三分对普通球员越划算，进攻方越容易用三分绕开护框。`THREE_BIAS` 就是为了拆开这两者。
- **投篮能力的价值不只看斜率**：中投的价值主要来自“过出手门槛”，三分的价值主要来自出手量搬家。
- **进攻斜率和防守斜率要分开**，助攻加成也不要挂在投篮斜率上，否则调一项会牵动另外两项。
- 每轮都要同时看真实名单的出手结构和助攻 / 抢断 / 盖帽，只盯敏感度会把比赛调得不像篮球。

## 位置与站位：全部由能力值决定

引擎里没有独立的“倾向”数值，也不看名单上写的位置（`role` 只是标签）。怎么打全部从能力值推导，所以可以摆“五个中锋”这类奇怪阵容：

- 站位（`src/sim/lineup.ts` 的 `assignSpots`）：每队五人按能力值分到五个站位。内线度 = 篮下 + 篮板 + 禁区防守 − 三分，最高的站低位（C 位）、第二站肘区（PF 位）；名单上写的位置（PG/SG/…）只是装饰，引擎不读；
  剩下三人里助攻最高的站弧顶（PG 位）；最后两人三分高的站 SG 位，另一个站 SF 位。球员脚下圆盘和球员卡上显示的是分到的站位。
  对位按站位序号，传球最差的人底线发球、传球最好的人接球。
- 移动速度按身高：185cm 及以下 1.0 倍，215cm 及以上 0.83 倍，中间线性。
- 突破倾向：`0.5 + (篮下 − 三分) / 60 + (助攻 − 70) / 200`，截断到 0.05~1；路线空时每次决策的突破概率 = 2% + 倾向 × 6%。
- 传球倾向：`(75 − 助攻) / 50 × 0.25` 的期望得分偏置，助攻越高越爱传。
- 出手选择：按期望命中率 × 分值，三分再乘 1.1；三分高的人自然更常出手三分，也更常站在三分线外（外线三人站中距离位的概率 = 0.7 + (中距离 − 三分) / 80；内线拉出三分线的概率 = (三分 − 38) / 130，上限 30%）。
- 无球跑位频率看稳定性；空切看篮下能力：概率 = (篮下 − 30) / 50（10%~90%），离篮筐 3.5m 内的人不切。喂内线的加分也按接球人的篮下能力算。

## 结构

- `src/sim/Match.ts`   规则与裁决：球权、24 秒、投篮 / 盖帽 / 犯规 / 篮板对抗 / 截断、发球、半场、统计
- `src/sim/ai.ts`      球员决策：持球人按“期望得分”在投/传/突/运之间选，无球人站位与空切，防守人盯人与抢断
- `src/sim/attrs.ts`   稳定性随机
- `src/sim/Player.ts`  球员本体：移动、软碰撞、姿态、渲染、个人数据
- `src/sim/Ball.ts`    球：运球、传球/投篮抛物线、落地滚动、篮板优先权
- `src/sim/court.ts`   球场几何（1 米 = 20 像素）、站位点、三分判定
- `src/sim/rng.ts`      带种子的随机数与种子链
- `src/replay/Timeline.ts` 每分钟快照与统计样本；拖进度条时恢复最近的快照
- `src/ui/StatsPanel.ts` / `PlayerCard.ts`  数据面板与球员卡
- `src/ui/ProgressBar.ts` / `StatsChart.ts`  进度条与分钟粒度统计折线图
- `scripts/replay-check.ts` 可复现性与快照完整性校验
- `src/sim/fatigue.ts` / `coach.ts`  体力系统 / 教练排出场时间与换人
- `src/season/`         球员库与球队库读取（`db.ts`）、赛季 / 季后赛 / 奖项（`Season.ts`）、后台模拟线程池
- `src/ui/season/`      赛季总览（HTML，盖在画布上；观看比赛时隐藏）
- `scripts/build-db.ts` 生成球员库 / 球队库
- `src/data/players.ts` 两队名单：基本信息、徽章、能力值、球员卡上的能力值说明（`ATTR_HELP`）。两队经名单互换测试校准到强弱相差约 1 分；改名单或改引擎后用 `SWAP=1` 对照一次再下结论

## 常用调参位置

- 半场时长 / 默认倍速：`Match.ts` 的 `HALF_SEC`、`MatchScene.ts` 的 `DEFAULT_SPEED`
- 出手意愿（节奏）：`ai.ts` `thinkHandler()` 里的 `threshold`，按 `Match.setTime()`（到前场之后的秒数）分段：
  前 7 秒先传导、11 秒后放开出手，突破和空位接球即投也从到前场 5 秒后才开始
- 命中率曲线与防守折损：`Match.ts` 的 `SHOT_CENTER`、`CONTEST_M`、`CONTEST_K`、`shotChance()`、`shotDefVal()`；三分偏好：`ai.ts` 的 `THREE_BIAS`
- 站位：`court.ts` `OFFENSE_SPOTS`
- 球员能力：`players.ts`
